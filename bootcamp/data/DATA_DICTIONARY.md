# EHS diabetes registry — data dictionary

`ehs_diabetes_registry.csv`: one row per patient, 4,000 rows, 54 columns. Synthetic, deterministic
(generated by `backend/scripts/generate_hie_data.py`), modelled on a diabetes registry across the
EHS network in the Northern Emirates. The same table drives the app's dashboard and assistant, so
an agent built on it in SAS Viya answers with the same numbers participants see in the app.

`ehs_facilities.csv`: the 18 facilities (id, name, type, emirate). `region` on the registry is the
facility's emirate, so most questions need no join.

On the bootcamp Viya the two tables are loaded in the `Public` caslib at global scope as
`Public.EHS_DIABETES` and `Public.EHS_FACILITIES`. Keep every team table in `Public` too: Model
Studio cannot read a personal caslib.

**Target for the ML model:** `deterioration_next_12m` (1 = a diabetes deterioration event in the
next 12 months: admission for hypo- or hyperglycaemia, DKA/HHS, foot infection or AKI, or
progression to HbA1c ≥ 10%). Event rate 10.4%.

**Leakage to exclude from model inputs:** `patient_id`, `full_name`, `last_visit_date`,
`open_care_gaps` (free text), and the rule-based registry score `legacy_risk_score` /
`registry_risk_tier` if you want the model to beat the registry tier honestly.
